# 2026-10-06 国内部署与连接故障记录

## 故障判断

目前没有发现恶意进程、异常启动项或木马检测告警。依赖安装造成的内存与磁盘压力是主要怀疑方向；故障前的资源采集未开启，日志中断，无法证明唯一根因，也不能据此保证主机从未被入侵。

- 故障前最后一段系统日志在 17:54:18，记录本次部署开始构建用户会话。
- 阿里云控制台记录 18:01:15 系统盘读写带宽达到上限；当时 SSH、HTTPS 同时不能完成响应。
- 用户于 19:43 重启主机，随后 SSH 恢复。主机实际可用总内存约 1.65 GiB，原先无 swap，`vm.swappiness=0`，同时运行 Pulse、PostgreSQL 和云监控。
- 前一启动周期的现存内核日志没有 OOM、磁盘 I/O 错误、EXT4 损坏或内核锁死记录。重启后的 journal 不完整关闭提示与强制重启相符，不能当作感染证据。
- 在独立 systemd 构建单元中复现了内存压力：低软限制使代码页面频繁回收、重复读盘；取消软限制但保留 900 MiB 物理内存上限后，安装器被该单元的 OOM 机制终止。之后增加交换空间、允许构建使用 512 MiB swap，仍达到限额。该证据来自重启后的受限重试，不能冒充故障前的整机 OOM 证据。
- 受限重试期间 SSH 与 Pulse `/readyz` 持续正常；没有重启或终止原有业务。
