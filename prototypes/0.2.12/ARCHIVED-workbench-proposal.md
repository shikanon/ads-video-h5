# 轻喵 0.2.12 工作区初稿（已归档，以 README.md 为准）

状态：交互设计评审。独立分支 `design/0.2.12-workbench-prototype`。当前原型不调用生产接口、不产生模型费用、不修改 0.2.11 的业务页面。

## 草图的落地方式

- 保留“画布 + Agent + 模板”的核心。手机采用上下布局：画布在上，Agent 与输入在下，模板作为可收起的选择面板；宽屏后续再使用左右分栏。手机不常驻细窄侧栏，避免挤压画布和触控区域。
- 画布是当前项目的结果区，包含生成的画风、样张和用户自己的作品；轻喵对话负责解释、补充需求和修改。画布与对话共享项目、素材、模型、任务与选中对象，不复制另一套会话。
- 点模板只填入可编辑的制作要求和必要参数，不直接执行。点击制作前显示本阶段费用并检查参考图。切换模板保留草稿；当前任务继续归属原项目。
- 图片点选、放大、拖拽和双指缩放属于画布操作；显示“适应画布”便于复位。文字输入时自动收起模板面板，防止键盘、面板、画布同时争夺空间。
- 自在聊天保留为同一创作页的轻量入口；从聊天转制作携带已选素材和上下文。制作中的项目持续运行，切页后恢复项目和选中状态。

旧功能合并入口，不删除用户数据、历史作品、普通聊天、私有素材处理或导出能力。项目内视频预览只展示用户自己的输入和生成结果，模板只展示静态工具卡、输入要求和产出类型，不引入公共视频观看列表。

## 表情制作的唯一流程

1. 点击“轻喵表情包画风”，输入框带入要求，用户补充自己的角色图。
2. 先检查原始参考图；不能使用时说明具体原因并给出替换建议，不盲目调用生图接口。
3. 以轻喵 24 张原始表情为画风来源，制作两种候选：柔彩精致 / 圆润萌系。两个候选属于同一个模板下的选择阶段。
4. Agent 询问用户选哪种；点击后锁定候选图、角色特征、画风与后续参考。不在整套中混合候选。
5. 按选中画风制作 3 张样张。用户可放大检查、提出修改；质量问题的修复保持当前项目和已付费成果。
6. 用户确认后才继续剩余 21 张；整套完成后导出。每一步分别显示积分，后台真实校验余额并使用既有幂等扣费规则。

互动表情默认单个完整角色与爱心或抱枕互动。不得通过凭空复制角色头部来表现“贴贴”。生成端和质量检查继续检查角色数量、完整身体、肢体/尾巴数量、画风、边缘与透明通道。

## 原型可体验内容

`workbench.fragment.html` 包含“画布优先”和“对话优先”两种布局。可选模板、选择两种画风、查看参考图检查建议、制作演示样张、确认整套、打开作品、返回继续、放大画布、拖动图像、切换输出格式和普通聊天。所有任务、积分、导出与上传均为本地演示，不代表真实生成。

图像使用上一版隔离验收中的既有图片，仅作为布局素材；不是本次新生成的作品。选择第二种画风时不伪造一套对应动作图片，只展示该画风锁定后的示意。生产实现须消费真实项目阶段和真实图片。

## 实施边界

先评审交互原型，再实施原生 WXML/WXSS/JS。复用 0.2.11 的画风候选、参考图检查、质量检查、积分和后台任务接口；补充统一项目工作区及恢复逻辑。导航、画布交互、面板和项目整合需要前端新版本；画风规则、检查建议和错误分类可更新后端。此阶段不上传微信、不部署生产、不提交审核。
