# 原素材音乐MV复刻

用户要求1:1复刻且存在原工程时，优先恢复原素材映射、逐镜时间线、裁切、速度、调色、推拉、转场、字幕与画幅。使用referenceEdit保存有界参数，由原工程渲染器逐节点制作。原切点中心叠化不扣减名义时长；不得改成自由分镜、重新挑选照片或用不同镜头凑时长。已恢复工程禁止重新调用自由编排覆盖。只有实际比较原片及输出后才能报告保真程度，解码通过不代表视觉一致。

字幕不能再次缩小画面或重复加黑边。原画幅、有效画面大小与位置在referenceEdit中固定；新增歌词只叠加在原有黑边内。原字幕字体不可用时可用经核验、账号内的真实透明字幕轨保留字形；不能把不透明参考成片伪装成字幕轨。歌词修改后复用原工程镜头节点。

入口：工具 → 音乐MV → 原素材复刻MV。使用 `/api/mv-recreations` 的持久化项目，不走口播精剪的60秒脚本链。输入参考片、独立配乐、1–100个账号内原素材和制作要求。参考片仅供分析，不能作视觉输出源。

文件夹调用：资源中可新建、改名、批量移入或删除素材文件夹，删除文件夹保留素材。将文件夹内的视频设为MV参考片、音频或视频设为MV配乐后，在音乐MV入口写一句要求，调用`POST /api/mv-recreations/from-folder`（folderId或完整文件夹名、prompt、requestId）。服务端仅解析当前账号的文件夹；多个同名片段匹配时要求点选，缺参考片或配乐时明确指引设置，禁止猜用别人的素材。文件夹绑定了原工程时复用原参数，直接制作样片；否则实际分析与分镜。样片确认后继续整片。回复“已完成”前必须有实际任务、输出文件及校验结果。

顺序：实际抽帧理解 → 带来源时间码的分镜 → 用户核对字幕与时间线 → 20秒样片 → 分节点渲染 → 平衡树合并或直切拼接 → 一次性合入原配乐 → 完整解码与音轨/时长检查 → 用户视觉验收。状态必须来自任务或文件收据；文字回复不等于视频。

每节点0.2–30秒，视频原始入出点不能越界；不得把多素材改成整段复制参考片。照片只作必要叙事镜头，视频优先，不生成或替换用户禁止生成的人物。按用户给定的故事结构组织，不能虚构游戏官设和跨镜头身份。

音乐连续、不循环、不变速，不混入原素材声音。未实测不能声称有某个BPM；未核对的歌词不要自动加入字幕。参考片稀疏抽帧只能证明采样处的画面，不能证明完整动作或逐镜精确时间。分镜编辑改变哈希，需重新确认。

字幕分为两层：参考片可见或用户提供的剧情文字用story，实际配乐识别的歌词用lyric。不要用四个章节标题代替原片的整层剧情字幕，也不要把剧情文字误当歌词。原片字幕文字与显示范围需完整提取后逐条核对，12张稀疏抽帧不足以声称提取完整。用户要求MV表现时使用subtitleStyle=cinematic：保留全画面比例、黑边内白色书法剧情字幕淡入淡出，歌词另占一行；有真实字词时间才使用逐词高亮。两层不得重叠。

歌词流程：分镜已保存后调用项目lyrics阶段，按所选配乐的真实音频分块识别并保存成功块；歌词草稿与已批准分镜分离，不自动视为校对完成。必须引导试听、改字、调整时间、删除误识别的间奏歌词，再采用草稿并制作样片。不能根据歌名、剧情或记忆补齐听不清的歌词。时间码是模型估计，不能把顺序/范围检查说成强制对齐或逐字准确。修改字幕仅更新合成层，已核验的相同画面节点继续复用。

节点与合并结果以内容哈希校验后复用；停止或失败后续做未完成部分。修改源文件、删除素材、账号切换后禁止沿用过期收据。只声明实际完成的技术检查，不将解码通过称为用户已接受或视觉复刻已达标。
