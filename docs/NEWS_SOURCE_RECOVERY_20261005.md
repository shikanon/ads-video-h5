# 新闻口述请求失败的修复与验收

用户截图中的请求是：制作介绍今天发生事情的大模型相关新闻口播视频，并说明选题依据。截图显示 26 次工具调用后停在 research，正文不足、交叉来源和时效校验均未通过，且系统反复锁定自行选择的候选。本文记录代码缺陷、真实网页核验与实际成片验收；没有读取截图对应账号在 19:03 的原始服务器日志。

## 确认的缺陷与修复

1. HTTPS 读取器把压缩正文当 UTF-8 文本。实际新湖南页面返回 gzip，旧读取结果是乱码。现先按响应头解压 gzip、deflate、Brotli，再按响应头或 meta 的编码解码；压缩前后均保留 1.5 MB 上限及公开地址、HTTPS、重定向校验。
2. 正文和日期抽取依赖正则，不能可靠处理嵌套内容和公告字段。现用 parse5 读取正文区域、JSON-LD articleBody、发布元数据与实际发布字段，区分发布时间和更新时间。华为公告的隐藏 `releaseFormatTime`、证券时报正文信息区的日期均可正确读取；客户端脚本空壳和登录页仍拒绝，主动换源。
3. 研究策略把 Agent 自行挑选的候选当成用户指定对象。现三轮不同查询区分用户领域和明确对象、版本；领域请求可淘汰旧闻或不可读候选并重选。固定对象则换同事件的可读来源。永久不可读页面不重复读取，临时服务或网络故障最多额外读取一次。证据校验拒绝后推进查证策略，不能在同一失败候选反复提交。
4. 视觉遗漏被误判为声音漏字，新闻返修受固定图解限制。现只重画实际受影响章节，可改变图解设计，并核验、复用正确旁白。
5. 字幕中的 `五g` 没有得到正确规范，音视频缓存又可能复活旧识别结果。现仅规范脚本中真实说出的相同代际、字母大小写，保持原始转写与时间跨度；缓存匹配也包含当前识别与分行结果。数字错误、漏字、音频文件哈希不符仍阻塞。
6. 单个金额错误地套用没有对应数据的比较柱图。现用真实金额和单位卡片呈现单值，完整定量柱图仍需经过验证的数据。
7. 合成旁白的声线审查可能误要求真人原声。现主题创作只比较实际成片中的各段声线，以首段为基准；音频不可辨或真正漂移仍拒绝，真人原声重构的参考要求保留。
8. 部署后用独立验收账号的新会话提交原始请求，研究、事实核查和实际渲染完成，但两轮审查分别耗时 524244 ms、726516 ms，后者明确返回语音请求超时、语义审查未完成。现仅将审听传输改成完整的单声道 16 kHz、128 kbps MP3，减少约一半音频载荷；原片、响度实测、转写、全部抽帧及评分门槛保留。不能仅据超时认定大载荷是唯一原因。[官方 API 文档](https://docs.volcengine.com/docs/ark/chat-api?lang=zh&redirect=1) 支持 MP3 `input_audio`。错误现在区分服务超时、HTTP 故障及无有效结果。点击重试时，只有审查未完成的既有成片直接进入 `review`，避免重新检索今天新闻和重做视频；真实内容缺陷仍进入返修。
9. MP3 补充版本在线上重试后，声音审听通过，语义审查仍明确超时。正常用户的公开媒体存储现在为审查租用临时音频与抽帧对象，用 API 支持的媒体 URL 读取；保留完整音频、全部原尺寸抽帧与相同质量标准，完成或失败后清理临时对象，原视频不重渲染。私有存储、未配置存储和管理员评测保持内嵌传输，评测资料不发布到公开 Bucket。审查记录增加请求字节数、耗时、状态和错误类别，禁止记录密钥、请求正文或临时媒体 URL。依据：[官方音频 URL 说明](https://docs.volcengine.com/docs/ark/audio-understanding?lang=zh)。

10. 跨零点复核曾把 10 月 5 日的原始指令误按 6 日验收，又把用户未要求的 BGM 当成阻塞项。现研究、事实审查、成片审查及返修均使用服务端保存的原始指令日期；真实抓取时间、来源年龄及新闻窗口仍按当前时钟检查。只有哈希验证通过的既有成片可复用仍在新闻窗口内、原指令事实验收通过的证据；新任务仍保留 30 分钟研究缓存门槛。真正内容缺陷会从 review 回到 export 返修。
11. 真实抽帧发现“六十九亿美元”被拆为“超六 / 十九亿美元”。现保护实际转写中同一已核验语句内的金额、单位和数量边界，保留原字词及时间码；“六；十九美元”这类不同语句保持分开，不补词、不改数值。

## 验证方法

新增 `news-spoken-llm` 保存用户原始口述句式，后台生产用例现共 31 条。三模型配置各执行同一受控读源恢复测试，覆盖首轮旧闻与不可读、次轮单发布者、第三轮可读交叉来源；这些不是三模型真实能力成绩。

默认豆包的实际生产评测执行真实研究、事实审查、配音、识别、HTML 图解、FFmpeg 渲染与独立音视频审查。全部失败与主动停止的记录均保留；后续从检查点重绘的运行如实标为 resume/redraw，并核验复用音频。浏览器完整播放、下载一致性、远程提交号及线上新会话另行验收，不能由本地测试成绩代替。

## 本地验收结果

462 项测试全部通过，H5 和管理端构建通过。用户原始口述指令的最终真实成片独立审查通过，84/100、45.09 秒、720×1280；不存在阻塞缺陷。最终运行从已核验检查点重绘，复用来源与音频，真实渲染和审听均重新执行，没有计作重新检索或三模型全量出片。

全片音视频解码通过；Chrome 从头有声播放至 `ended=true`，首、中、尾画面与字幕检查通过，浏览器无错误日志。下载文件与实际导出文件 SHA-256 相同：`785e4538b4af4d140cffe5431bf65b91a5e52dd932a3baa4204ef136393c160f`。本轮早期生产尝试及中断记录均保留，未使用失败版本较高评分替代最终验收。以上为部署前本地验收，线上验收使用独立账号的新会话和原始请求另行执行。

审查传输补充修复后 463 项测试通过，新增真实 FFmpeg 编解码测试验证审听范围、载荷、格式和原文件未变。同一份已验收的本地成片复制到独立审查路径，完整音频和抽帧重新评审通过，88/100，原成片哈希不变；这是传输修复验证，没有计为重新研究或重新渲染，线上补充复验单独记录。

媒体 URL 补充版本 468 项测试、H5 和管理端构建通过。新增真实音频与抽帧字节验证、失败与取消时的临时对象清理、评测和私有存储隔离，以及诊断信息不含密钥或媒体 URL 的回归测试。线上原视频的最终审查结果另行记录，测试通过不能代替线上通过。

跨日与字幕补充版本 471 项测试、H5 和管理端构建通过。真实旧片在跨日复核中曾返回 83、74 分，相关失败原件均保留；按原始指令日期修正验收上下文、保护金额断句后，复用已核验来源、原旁白和图解，仅真实重渲染字幕与成片，独立音视频审查通过 88/100，无阻塞项。此运行不是重新检索、重新配音或三模型 Agent 出片对比，线上媒体 URL 审查另行验收。
