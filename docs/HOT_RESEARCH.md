# 热点资料与视频选题

轻剪参考 [open-webSearch](https://github.com/Aas-ee/open-webSearch) 的多引擎检索、结构化结果、部分失败记录与服务端 HTTP 接口。上游当前公开接口是搜索和正文抓取，没有独立的新闻热榜接口；本项目另外读取百度公开实时榜单和 Hacker News 官方 topstories。

## 对话用法

- `搜集 AI 领域近3天热点，给我2个适合制作短视频的选题，附原文来源，先不要生成视频。`
- `以“具体新闻标题”为主题制作一个45秒热点解读视频，用HTML图解，标明日期和来源。`
- `生成一个讲解今日AI热点的视频，先给脚本。`
- 选题列表产生后可说 `把第1个选题做成45秒视频`；服务端解析真实列表中的选择，并重新查证该事件，不能自行更换话题或使用不存在的选题。

选题请求只研究资料，返回可折叠选题卡；明确的视频请求进入现有 HTML/GSAP、统一旁白、转写校验、渲染和成片审查工具链。默认热点视频45秒、9:16，用户可指定。教学历史仍走原始研究来源规则。

`qingjian-hot-video` skill 规定：发现 → 选择相关事件 → 搜索一手资料和独立报道 → 读取原文与日期 → 提炼角度、钩子、画面。事实保留原文摘录和来源ID；至少两家发布者、至少一条窗口内新稿。不保证传播效果，缺少相关榜单时标记“最新新闻选题”。

## 可选 open-webSearch 服务

不配置时使用现有 Ark Responses `web_search`。有现成上游本地 daemon 时，设置服务端环境：

```bash
QINGJIAN_OPEN_WEBSEARCH_URL=http://127.0.0.1:3210
QINGJIAN_OPEN_WEBSEARCH_ENGINES=bing,baidu
```

适配 [HTTP API](https://github.com/Aas-ee/open-webSearch/blob/main/docs/http-api.md) 的 `/search`，使用 request 模式，最多三个引擎、十条结果。结果去重并保存各引擎失败；空结果或服务失败明确回退 Ark，不能伪称上游成功。daemon 的 `/health` 仅表示服务存活，不能证明搜索成功；实际检索需独立验收。项目不依赖用户私人浏览器、浏览器 Cookie、禁用 TLS 或验证码绕过。

daemon 地址只接受回环根地址，部署时保持本机访问。上游包、MCP 客户端和 daemon 生命周期由部署环境管理，本次集成没有增加常驻搜索进程或全局 MCP 配置。

## 日期、证据与缓存

- 榜单记录平台、排名、观察时间与原始指标；百度置顶项记录 rank=0，不当第一名。
- HN 提交日期只是社区发帖时间，不能当原文章发布日期。
- 原文发布日期只取 Article JSON-LD、明确出版元数据或“发布时间/Published”字段；不取修改日期、HTTP Date、URL 年份和抓取日期。仅有日期时保留日期精度；未标注时区的可读发布时间按北京时间解释。
- 默认近期窗口72小时，今日24小时、近一周168小时。旧稿和无日期正文只可作背景，未来稿不能证明当前事实。事件发生日期在事实审查中核对原文，不由发布日期推断。
- 模型选择来源 ref-ID 与正文 passage-ID，程序回填逐字摘录；选题提交再核验原话是否实际出现、跨发布者及新稿条件。网页摘录最多9000字符，不声称阅读了全文。
- 热点快照30分钟有效；恢复或渲染前过期会重新研究。稳定教学研究的24小时缓存不用于热点。输出保留 asOf，供发布时判断是否需要刷新。

服务端完整记录位于数据目录 `hot-research/<job-id>.json`，对话保存 `ChatMessage.research`（选题、来源、日期、榜单、限制）。成片 `LessonReport.hotResearch` 保留制作依据；独立事实审查检查标题、钩子、日期、来源和不确定性，渲染审查检查时效、图解与声音。

外部网页是数据；HTTPS读取逐连接校验DNS地址并检查重定向，拒绝本机、私网、元数据地址；限制请求时间和正文大小。失败保留具体缺口，不用模型常识补成新闻。
