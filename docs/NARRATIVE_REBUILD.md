# 重构知识短片

页面上传视频后，一句指令即可启动：

> 把企业AI落地重构成36秒知识短片，联网补充，用我的声音，直接出片。

无需在对话中枚举工具或逐镜输入台词。`qingjian-narrative-rebuild` 根据素材选择一个观点，检索完整原话，以 Ark Responses `web_search` 查证缺口，再提交 original/generated 混合脚本。原声分镜保留原话、源时间、源哈希和选择理由；新增台词明确标记新增并引用实际搜索返回的 ref-ID。`用我的声音` 是声音参考的授权，不允许 skill 自行捏造授权。

新增配音通过 Seed Audio 1.0 `references: [{audio_data: base64}]` 与 `@Audio1` 使用3–25秒的所选录音参考。每段音频实测时长后，Seed 2.1 Lite 再转写核对实际说出的文字。禁止用预期文案冒充转写，失败也不降级为默认音色。真人原话可用原画面或由原音驱动的 HTML 分镜；新增台词用 HTML 示意，避免出现错误嘴型。

模型提交受约束的 DOM/SVG 节点、布局、文字和高亮，系统编译为暖白、深墨、珊瑚色的 GSAP/HyperFrames HTML，绘制因果连线、流程节点和步骤高亮。文本转义、节点ID、范围和字号都经校验，不执行模型提供的任意脚本。输出 HTML、布局 JSON、实际音频及媒体哈希存于 `data/narrative-scenes/<workflowId>/`。重构竖屏输出720×1280；编排按原句与配音实测时长，不剪掉尾字硬凑36秒。

渲染后核对方案哈希、完整音轨、字幕映射、引用、HTML执行以及完整音频与各镜关键抽帧。需要修复时只改相关镜头，实际再渲染一次，保留评分与检查更好的版本。页面展示完整重构脚本、原话/新增区别、来源链接和可下载剪辑记录。

每个 HTML 分镜先执行 HyperFrames lint 和布局检查，保存检查 JSON 后以 standard 质量渲染。卡片使用独立 HTML 节点，连线使用 SVG，避免 foreignObject 中空节点序列化导致嵌套错位。工作流按任务保存检查点；同一任务中断后，可用原素材哈希和用户指令验证后继续，完成的任务不会被当作新的剪辑结果复用。

生产阶段如发现台词不匹配、成果样例缺失或实测时长偏差，Agent 调用 `refine_script` 更新对应分镜，保留完整原话和引用，再生成、编排和审查。转写失败保留已注册的实际分镜，按脚本规格与 HTML 哈希验证后重试音频理解。新增音频的素材标题只用于消歧同音词，不向识别模型提供预期逐字稿。

已知边界：搜索引用不是独立网页全文核查；源字词时间仍为模型估计；参考声音不保证完全复刻；生成界面和成果标记示意，不代表实际产品效果。时长差异和审查失败写入记录，不能把所有检查通过当作专业级成片。

声音验收独立于台词准确性。`review.audio` 保存真实成片逐段LUFS、真峰值、有声窗起伏、段间差值，以及参考音色与段间音色的专门听辨结果。归一化改为逐段测量/处理两遍，再对实际混音测量/处理两遍；不能只检查normalize标志或整片平均LUFS。音频在测量滤镜前按分镜时长裁齐，防止滤镜缓冲读到后一个分镜。默认编辑门槛为段间极差≤2.5 LU、相邻段综合差≤2 LU、有声窗P90−P10≤8 LU，编码后真峰值≤−1 dBTP；这些是本项目编辑策略，不是通用标准。

音色审听把真实原声参考与真实成片各段组成匹配音量的串联音频，记录每段音高、共鸣、口音和录音空间差异。同一referenceHash不是音色相似的证据。缺参考、缺结果、失败或uncertain都不能默认通过；必需声音项失败时整片仍为needs-review。音量修复不能承诺修复音色；音色返修会递增voiceRevision，使对应新增段的TTS和分镜缓存失效，重新合成并再转写。听辨为定性判断，不是声纹认证。带BGM成片的混音可能影响声音测量和听辨，当前不进行独立人声分离。

规划 Agent 的 Seed 2.1 Pro 上下文为1,024,000、最大输出262,144；Lite 最大输出256,000。Ark 请求明确使用 `max_tokens`，与 SDK 的其他兼容字段区分。输出上限与上下文窗口是两个参数，提高输出上限不能单独消除上下文截断。后台将长素材证据持久化、工具按需返回检索结果；保留 SDK 对真实剩余上下文的预算检查。Pro 的262,144参数已通过实际 Chat API 调用。

归一化前先将每段预增益到约−18 LUFS，原录音施加温和压缩；合成段从温和压缩开始实测，必要时尝试较强候选，优先选择达到起伏门槛且留有编码余量的温和方案，随后两遍响度处理。渲染清单保存实际预处理滤镜与测量参数。用户明确指出音色不似时，将拒绝记录关联到合成音频哈希；模型判断不能覆盖该反馈。仅调音量、换视频版本或再次导出不会清除拒绝；重新合成后用新音频再次审查，旧投诉不会无条件否决所有未来声音。

直切拼接单独按计划时长裁齐音频采样后连接，不使用视频容器时长累计声音偏移，避免AAC填充使后续声音错过字幕和检查边界。真实编码后成片仍再次逐段测量，候选处理效果不代表整片验收已通过。

## HTML 画面路由与验收

知识讲解、知识短片、科普视频、HTML 分镜、流程图或场景示意图请求进入混合制片工作流；独立开场特效仍走模板库，忠实精剪仍走口播选句流程。普通“生成视频”若没有上述要求或同一会话的知识制片上下文，仍属于素材剪辑，不保证生成新画面。短导出指令继承最近用户的 HTML 要求；助手回复不能建立这种要求。用户明确取消 HTML 时停止继承。

只重绘画面默认使用完整原句与原片音轨，跳过联网补充和声音合成；例如“制作10秒知识讲解视频，保留原声，用流程图呈现需求确定化，直接出片”。原声 sentenceIds 必填，referenceIds 为空。禁止重复同一句原话来凑时长。需要联网补充新台词时，仍使用带引用的研究和已授权声音参考。

计划与导出共用 narrative 工作流，并实际加载 qingjian-html-video skill。脚本、检查点恢复、返修至少保留一个 HTML 分镜；`produce_scenes` 渲染后记录 HTML/audio 哈希，时间线引用生成媒体，成片审查同时核对这三者。零个 HTML 分镜不再通过“HTML分镜执行”检查。

HTML 最终先渲染为 MP4，再作为片段加入时间线，因此时间线显示“视频素材”不代表只复用原视频。应检查素材的 `generation.htmlHash`、对应 `narrative-scenes/<workflowId>/<beatId>/index.html` 和 `reconstruction.beats[].visual`；字幕/透明圈注属于覆盖层，不等同于完整新画面。
